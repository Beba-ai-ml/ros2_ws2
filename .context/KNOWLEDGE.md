# SAC Driver - Knowledge Base

## Architecture

### Full System Diagram
```
                     JOYSTICK
                        │
                        ▼
┌─────────────────────────────────────────────────┐
│              joy_mode_manager                    │
│  LB (btn 4) → manual mode (gates teleop)        │
│  RB (btn 5) → autonomy mode (unlocks /drive)    │
│  Logic: lock = NOT autonomy_active OR manual     │
│  Publishes at 50Hz to /autonomy_lock             │
└───────────┬───────────────────┬─────────────────┘
            │                   │
    /teleop_gated          /autonomy_lock
    (priority 100)         (Bool: True=locked)
            │                   │
            ▼                   ▼
┌─────────────────────────────────────────────────┐
│              ackermann_mux                       │
│  joystick channel: /teleop_gated (priority 100)  │
│  navigation channel: /drive (priority 10)        │
│  lock: /autonomy_lock (blocks navigation)        │
│  Output: /ackermann_cmd → VESC                   │
└─────────────────────────────────────────────────┘
            ▲                   ▲
    /teleop_gated              /drive
            │                   │
     joy_teleop           sac_driver_node
     (manual)             (autonomous)
```

`scripts/key_drive.py` also publishes on `/teleop_gated` — priority 100, so it bypasses the
joystick deadman and is **not** masked by `/autonomy_lock`.

The mux publishes on `ackermann_cmd`; the `ackermann_cmd_out` → `ackermann_drive` remap in
`bringup_launch3.py` is a no-op, and `ackermann_to_vesc_node` subscribes to `ackermann_cmd`,
so the chain works.

### SAC Driver Internal Architecture
```
ROS2 Topics (async)          Timer (30Hz)              VESC
┌──────────┐                ┌─────────────────┐
│ /scan    │──→ latest_scan │                 │
│ /odom    │──→ latest_speed│  _on_timer():   │
│          │──→ latest_accel│  1. LidarConv   │     ┌──────────┐
│          │──→ latest_yaw  │  2. StateBuilder│────→│ /drive   │
│ /servo   │──→ latest_servo│  3. NN inference│     │(Ackermann│
│ /autonomy│──→ enabled     │  4. ControlMap  │     └──────────┘
│  _lock   │                └─────────────────┘
└──────────┘
```

- **Async callbacks** store latest sensor values (no queuing, always overwrite)
- **Timer at 30Hz** grabs latest values, builds observation, runs NN, publishes command
- **Frame stacking**: sliding window of 4 frames (deque), each frame = 455 floats
- **Total state**: 455 x 4 = 1820 floats fed to GaussianPolicy neural network
- **Lidar is ~8Hz, odom ~50Hz** — between lidar updates, timer reuses last scan but gets fresh speed/accel/yaw

## Observation Vector (per frame = 455 floats)

```
[0-449]   450x lidar rays (dist / 20.0, clipped [0,1])
[450]     speed_norm (abs(speed_mps) / max_speed_mps, [0,1])
[451]     steer_norm (servo centered at 0, [-1,1])
[452]     accel_feedback (previous NN accel output, raw [-1,1])
[453]     linear_accel (accel_mps2 / max_accel, clamped [-1,1])
[454]     angular_vel (yaw_rate_rad_s / max_yaw_rate, clamped [-1,1])
```

## Lidar Angles (450 rays, variable resolution)
```
Front hemisphere (0-180°): 361 rays at 0.5° step
Rear hemisphere (182-358°): 89 rays at 2.0° step
Generated by build_lidar_angles(0.5, 2.0)
```
With **0° offset** (no rotation). Angle wrapping to [-pi, pi) in `_to_scan_angle_rad`.
Max range 20m. Interpolation enabled.

**CRITICAL: offset=0° for the current models** — they use the 0°=forward convention.
The old 27-ray model used 90°=forward (needed -90° offset). Verified experimentally with the
cardboard test: offset=-90 steered INTO obstacles, offset=0 steered AWAY correctly.

## Models
- **Active:** `src/sac_driver/weights/session_Rybnik_02_1.pth` — trained on the Rybnik_02 map
- **Previous:** `src/sac_driver/weights/session_car_1_3.pth` — R_01 map, 5368 episodes, with an
  OpponentBot (Pure Pursuit from ep 1500)
- **Architecture:** GaussianPolicy MLP [512, 512, 256], action_dim=2
- **action_scale:** [1, 1], **action_bias:** [0, 1] → steer [-1,1], accel [0,2]
- **Checkpoint format:** sac_checkpoint_v1, keys include policy/critic/optimizer states
- Weights are **tracked in git** (`.gitignore` has `!src/sac_driver/weights/*.pth`) and
  installed into the package share dir by `setup.py`, so `model.path` can be relative

## Model Path Resolution
`model.path` is resolved by `_resolve_path` in `sac_driver_node.py`:
- relative (e.g. `weights/session_Rybnik_02_1.pth`) → `<install>/share/sac_driver/`, with the
  source tree `src/sac_driver/` as a fallback when the package has not been rebuilt yet
- absolute paths, `~/...`, and `package://sac_driver/weights/...` also work
- override at launch: `ros2 launch sac_driver sac_driver.launch.py model_path:=/abs/x.pth`

**After adding a new .pth you must rebuild** (`colcon build --packages-select sac_driver`) for
it to land in the share dir.

## Key Files

### `src/sac_driver/sac_driver/` (ROS2 package source)
- **`sac_driver_node.py`** — Main ROS2 node. Subscribes to /scan, /odom, /servo, /autonomy_lock. Runs 30Hz timer loop. Computes linear_accel from odom speed delta. Builds state, runs inference, publishes /drive. Resolves `model.path`. Has debug logging for data readiness and autonomy state transitions.
- **`state_builder.py`** — Builds 455-element observation frames (450 lidar + 5 state channels), maintains 4-frame sliding deque. Normalizes all inputs. Returns concatenated 1820-float state vector.
- **`lidar_converter.py`** — Extracts 450 angles from LaserScan using `build_lidar_angles()` with variable step (0.5° front, 2.0° rear). Applies `lidar.angle_offset_deg` with wrapping to [-pi, pi). Returns normalized [0,1] distances.
- **`inference_engine.py`** — Wraps GaussianPolicy. Takes 1820-float state, returns (steer, accel). ~5-6 ms on the Jetson CPU. Generic, no hardcoded dimensions.
- **`policy_loader.py`** — Loads .pth checkpoint, auto-detects state_dim/action_dim/hidden_sizes from weight shapes. Handles `torch.compile` `_orig_mod.` prefix stripping. Includes `numpy._core` compatibility alias for PC→Jetson checkpoint loading.
- **`control_mapper.py`** — Maps NN output [-1,1] to Ackermann commands. Rate limiting, speed limiting, safe mode scaling, wheelbase-aware yaw rate. `speed_sign` / `steer_sign` flip directions.

### `src/sac_driver/config/`
- **`driver_params.yaml`** — all ROS2 parameters (model, lidar, state, control, topics, safety)
- **`driver_params_27ray.yaml`** — the old 27-ray / 120-dim model configuration

### `src/f1tenth_stack/`
- **`f1tenth_stack/joy_mode_manager.py`** — gates teleop with the LB deadman, controls the autonomy lock with RB. Publishes `/autonomy_lock` at 50Hz. Logic: `lock = NOT autonomy_active OR manual_active`.
- **`launch/bringup_launch3.py`** — main bringup: sllidar_node, vesc_driver_node, ackermann_to_vesc_node, vesc_to_odom_node, joy_linux_node, joy_teleop (patched copy via PYTHONPATH), joy_mode_manager, ackermann_mux, static TF `base_link`→`laser` (0.27 0 0.11). `throttle_interpolator` is present in the file but commented out.
- **`config/vesc.yaml`** — `speed_to_erpm_gain: 1850.0`, `steering_angle_to_servo_gain: -0.9`, `steering_angle_to_servo_offset: 0.5304`, `speed_min/max: ±45250.0`, `servo_min/max: 0.05/0.95`, `wheelbase: 0.35`, `throttle_interpolator.max_acceleration: 9.5`
- **`config/joy_teleop.yaml`** — `human_control` deadman `[4]`, speed axis 1 scale `-5.0`, steer axis 3 scale `0.34`; the `default` command has no deadman (needs the patched joy_teleop)
- **`config/mux.yaml`** — navigation `drive` prio 10, joystick `teleop_gated` prio 100, lock `autonomy_lock` prio 100, timeouts 0.2/0.3 s
- **`config/sensors.yaml`** — legacy Hokuyo/`urg_node` settings, not used by the current bringup

### `src/ackermann_mux/`
- C++ mux with priority channels. Joystick (priority 100) overrides navigation (priority 10). Lock topic blocks the navigation channel.

### `local_python/`
- **`joy_teleop/joy_teleop.py`** — patched copy of the Foxy node. Upstream raises when a command has no deadman buttons/axes; the patch marks such commands `always_active = True`. `joy_teleop.yaml` relies on it, so **the bringup fails without it**. `bringup_launch3.py` prepends `<ws>/local_python` to PYTHONPATH for that node. Do not resync with upstream.
- **`gpio_shutdown.py`** — drives BOARD pin 37 high, watches pin 38, powers the Jetson off after 0.2 s high. Root, via `gpio-shutdown.service`.

### `scripts/`
- **`key_drive.sh`** — device permissions, pauses `key_drive.service`, builds `f1tenth_stack`, starts/reuses bringup, waits for `/sensors/core`, runs `key_drive.py`; cleans up on exit unless `KEEP_BRINGUP=1`
- **`key_drive.py`** — 20 Hz `AckermannDriveStamped` on `/teleop_gated`. Backends: evdev (`--evdev`, hot-plug safe, used by the boot service), X11 `XQueryKeymap` (NoMachine, `DISPLAY=:1004`), terminal fallback (`--no-x`). `SPEED_SIGN = -1.0`. Defaults `--speed 2.0`, `--max-speed 4.0`, `--steer 0.3`.
- **`key_drive_boot.sh`** — systemd entry point: kills leftovers, waits for `/dev/vesc`, bringup, waits for `/sensors/core`, `key_drive.py --evdev --no-quit-key`, supervises the VESC chain and exits non-zero so systemd restarts it
- **`key_drive_test.py`** — automated forward/reverse/left/right check (wheels off the ground) using `/sensors/core` ERPM and `/commands/servo/position`
- **`ledy.py` / `ledy2.py`** — 7x WS2812B over SPI1 MOSI (pin 19, `/dev/spidev0.0`), violet

### `system/` (installation templates, `@USER@`/`@HOME@`/`@WS@` substituted by install.sh)
- `udev/99-f1tenth.rules` → `/dev/rplidar` (CP210x `10c4:ea60`), `/dev/vesc` (STM32 VCP `0483:5740`), both `MODE:="0666"`
- `systemd/key_drive.service.in`, `systemd/gpio-shutdown.service.in`
- `sudoers.d/f1tenth.in` → NOPASSWD for `shutdown`, `systemctl start|stop|restart key_drive.service`, `chmod 666 /dev/vesc|/dev/rplidar`
- `desktop/ROS2-Panel.desktop.in`

### `tools/`
- `vesc/vesc_config_upload.py` + `vesc/configs/*.xml` + `vesc/params/6.02/` — VESC config upload over serial, no VESC Tool GUI
- `lidar_diag.py`, `lidar_test.py` — direct-to-device lidar diagnostics

## How to Run

### Prerequisites
- **Bringup must be running first** — provides lidar, odom, vesc, joystick nodes
- **Model weights are local and tracked in git** at `src/sac_driver/weights/` (no NFS dependency)
- Required ROS2 topics active before launching sac_driver:
  - `/scan` (sensor_msgs/LaserScan) — lidar, ~8Hz, RELIABLE QoS
  - `/odom` (nav_msgs/Odometry) — speed + yaw rate, ~50Hz
  - `/commands/servo/position` (std_msgs/Float64) — servo commands (only publishes when the car is driven)
  - `/autonomy_lock` (std_msgs/Bool) — joystick deadman switch, 50Hz from joy_mode_manager

### Build
```bash
cd ~/ros2_ws && source /opt/ros/foxy/setup.bash && colcon build --packages-select sac_driver
```

### Run via launch file (preferred)
```bash
source /opt/ros/foxy/setup.bash && source ~/ros2_ws/install/setup.bash
ros2 launch sac_driver sac_driver.launch.py            # optionally model_path:=/abs/x.pth
```

### Run the node directly (MUST include --params-file!)
```bash
ros2 run sac_driver sac_driver_node --ros-args \
    --params-file ~/ros2_ws/src/sac_driver/config/driver_params.yaml
```
**CRITICAL:** without `--params-file` the node has NO model path and NO config → it only prints
"model.path is empty" and does nothing.

### Keyboard driving
```bash
~/ros2_ws/scripts/key_drive.sh                  # bringup + keyboard teleop, q quits
KEEP_BRINGUP=1 ~/ros2_ws/scripts/key_drive.sh   # leave bringup running
```

### Enabling autonomous driving
- Node starts **disabled** (`control.enable_on_start: false`)
- **Hold RB** (button 5) AND **release LB** → `/autonomy_lock` = False → sac_driver enables
- **Release RB** → `/autonomy_lock` = True → immediate stop
- **LB overrides** — manual takes priority
- Without a joystick: `ros2 service call /sac_driver/enable std_srvs/srv/SetBool "{data: true}"`

### ROS2 interface summary
| Direction | Topic | Type | QoS | Purpose |
|-----------|-------|------|-----|---------|
| Subscribe | `/scan` | LaserScan | RELIABLE (10) | Lidar ranges |
| Subscribe | `/odom` | Odometry | RELIABLE (10) | Speed, yaw rate, accel (derived) |
| Subscribe | `/commands/servo/position` | Float64 | RELIABLE (10) | Servo position commands |
| Subscribe | `/autonomy_lock` | Bool | RELIABLE (10) | Deadman switch (True=stop) |
| Publish | `/drive` | AckermannDriveStamped | RELIABLE (10) | Steering + speed to mux |
| Service | `/sac_driver/enable` | SetBool | — | Manual enable/disable |

### Bringup management
- **Panel:** `python3 ros2_panel/panel_app.py` (or `ros2_panel/ros2panel`)
- Panel manages: SETUP, Bringup, SLAM, AI Inference, Localize, Pursuit, Stanley; battery bar
  from `/sensors/core` `voltage_input` (12V=100%, 9V=0%); zombie killer on stop
- **Kill zombie nodes after bringup stop:**
  `pkill -f sllidar && pkill -f vesc && pkill -f joy && pkill -f ackermann_mux`

## VESC Configuration

### Hardware
- **VESC HW:** 6.0 (HW60), **Firmware:** 6.02, **Serial port:** `/dev/vesc`

### Config Upload Tool
- **Script:** `tools/vesc/vesc_config_upload.py`
- **Usage:**
  ```bash
  python3 tools/vesc/vesc_config_upload.py --check-sig
  python3 tools/vesc/vesc_config_upload.py --motor tools/vesc/configs/motor_config.xml --dry-run
  python3 tools/vesc/vesc_config_upload.py \
      --motor tools/vesc/configs/motor_config.xml \
      --app   tools/vesc/configs/app_config.xml --verify
  ```
- **How it works:** parses the FW 6.02 parameter definitions in `tools/vesc/params/6.02/`,
  serializes the XML config values into the VESC binary protocol, and sends
  `COMM_SET_MCCONF` (0x0D) / `COMM_SET_APPCONF` (0x10)
- **Safety:** CRC32 signature verification ensures the config structure matches the firmware;
  `--verify` reads the config back and compares all values
- Motor: 189 params (49 changed from defaults). App: 187 params (23 changed).
  Signatures on this car: Motor `0x2E43A161`, App `0x1D003A2C`

### Key Motor Config Values
- Motor type: FOC (2); current max 52.78 A, min -52.78 A, abs max 79.17 A
- Battery cut start 10.2 V, end 9.0 V
- FOC observer gain 1.61e9, motor R 0.0118 Ω, L 3.59 μH

### Key App Config Values
- Controller ID 97, app to use 3 (PPM + UART), servo out enabled, permanent UART enabled

## Conventions
- **Vendored upstream packages are off-limits for refactoring:** `sllidar_ros2`, `slam_toolbox`,
  `range_libc`, `particle_filter`, `f1tenth_system`, `src/scripts`
- **All normalization params come from config** — no magic numbers in code
- **policy_loader auto-detects architecture** — never hardcode state_dim/hidden sizes
- **No hardcoded `/home/laptop` paths** — derive from the package share dir, `__file__` or `~/ros2_ws`
- **No passwords in the repo** — privileged actions use `sudo -n` + `/etc/sudoers.d/f1tenth`
- **Variable naming:** `sensor_accel`/`sensor_yaw` for sensor readings vs `accel` for NN output
- **Accel feedback:** previous NN acceleration output (raw, before scaling) fed back as an observation channel
- **All subscriptions use RELIABLE QoS (depth 10)** — NOT `qos_profile_sensor_data`
- **Python 3.8 / torch 1.13 / ROS2 Foxy APIs only** — no 3.9+ syntax, no torch 2.x or Humble-only features

## Debugging Lessons Learned

### QoS Mismatches (CRITICAL)
- **NEVER use `qos_profile_sensor_data` (BEST_EFFORT)** for subscriptions on this Jetson — even
  though the lidar publishes RELIABLE, BEST_EFFORT subscribers silently miss messages. Use QoS
  `10` (RELIABLE) for all topics.
- Symptom: `scan=False` in data_ready logs despite `/scan` existing with publishers.

### Model Loading
- Models saved on the PC with newer numpy (`numpy._core`) — fixed with a `sys.modules` alias in `policy_loader.py`.
- **PyTorch format compatibility:** PC checkpoints saved with PyTorch 2.x have a `.format_version`
  file that PyTorch 1.13 rejects. Fix: repackage the zip without
  `.format_version`/`.storage_alignment`/`.data/serialization_id`, keeping all files under a
  subdirectory (e.g. `session_car_1_3/data.pkl`).
- `model.weights_only: false` is needed for full checkpoint loading.
- Auto-detection: `backbone.0.weight.shape[1]` → state_dim, `mean_layer.weight.shape[0]` → action_dim.
- `torch.compile`d checkpoints carry an `_orig_mod.` key prefix — stripped by `policy_loader.py`.

### Bringup / Node Lifecycle
- `ros2 launch` spawns nodes in separate process groups — killing the launch process does NOT kill the nodes.
- Zombie nodes hold USB ports (lidar, VESC) and cause subsequent launches to fail silently.
- Always `pkill -f sllidar && pkill -f vesc && pkill -f joy && pkill -f ackermann_mux` before re-launching.
- **Only one process may own `/dev/vesc`.** `key_drive.sh` stops `key_drive.service` for the
  duration of a manual session; `key_drive_boot.sh` kills leftovers before starting.
- NFS mount (`/home/laptop/shared`) may disconnect after reboot — check with `mount | grep nfs`,
  remount with `sudo mount /home/laptop/shared`. Not needed for inference.

### joy_teleop
- The Foxy node rejects commands with no deadman buttons/axes; `joy_teleop.yaml` has one
  (`default`). The patched copy in `local_python/` marks them always active. `bringup_launch3.py`
  puts `local_python` on PYTHONPATH; it warns if the directory is missing.

### _publish_stop Guard
- `_publish_stop()` has a `_last_stop_sent` guard that suppresses repeated stop logs, which makes
  state transitions invisible. Debug logging was added: `_on_estop` logs "Autonomy
  ENABLED/DISABLED", `_on_timer` logs "Waiting for data: scan=X odom=Y servo=Z".

### Speed/Steer Sign
- `control.speed_sign` and `control.steer_sign` flip the NN output direction.
- **On this car a positive `AckermannDrive.speed` = REVERSE.** Hence `speed_sign = -1.0` in
  `driver_params.yaml` and `SPEED_SIGN = -1.0` in `scripts/key_drive.py` — they must agree.
- **Current models:** `speed_sign=-1.0`, `steer_sign=+1.0`, `angle_offset_deg=0.0`
- **Old 27-ray model:** `speed_sign=-1.0`, `steer_sign=-1.0`, `angle_offset_deg=-90.0`
- The steer sign change followed the offset change from -90° to 0° (the rotation flip cancels
  the old sign flip).

### Lidar Angle Offset (CRITICAL)
- Current models: offset = 0° (0°=forward). Old 27-ray model: offset = -90° (90°=forward).
- Diagnosed with the cardboard test: obstacle at front-right (-33° lidar frame), offset=-90
  steered INTO it, offset=0 steered AWAY. Always verify the offset when switching models.
- `ros2_panel/scan_test.py` prints the 20 closest scan points to check the frame.
